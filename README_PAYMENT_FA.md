WALTRIX — آماده‌سازی انتشار و پرداخت
====================================

ساختار
------
- index.html: رابط اسکنر و بخش اشتراک
- server/server.js: سرور Express، ایجاد سفارش، اتصال زرین‌پال، تأیید سمت سرور
- server/.env.example: الگوی تنظیمات محرمانه (نمونه؛ مقادیر واقعی ندارد)
- server/data/: پایگاه داده SQLite در زمان اجرا ساخته می‌شود

اجرای محلی
----------
1) Node.js نسخه 20 یا بالاتر نصب باشد.
2) وارد پوشه server شوید.
3) دستور npm install را اجرا کنید.
4) فایل .env.example را به .env کپی کنید.
5) SESSION_SECRET را با یک مقدار تصادفی حداقل 32 کاراکتری عوض کنید.
6) تا زمان دریافت پذیرندگی، ZARINPAL_SANDBOX=true بماند.
7) برای تست قیمت‌ها را در WALTRIX_MONTHLY_PRICE_TOMAN و WALTRIX_YEARLY_PRICE_TOMAN وارد کنید.
8) PUBLIC_BASE_URL را برای تست روی نشانی HTTPS عمومی/تونل امن خود قرار دهید.
9) npm start را اجرا کنید.
10) سایت از همان سرور روی پورت تعیین‌شده باز می‌شود.

تنظیم درگاه واقعی
-----------------
- پذیرندگی باید به نام صاحب قانونی کسب‌وکار و با تأیید ارائه‌دهنده درگاه ایجاد شود.
- ZARINPAL_MERCHANT_ID را فقط در .env سرور قرار دهید؛ هرگز در HTML یا Git نگذارید.
- پس از تأیید مجوزها و پذیرندگی، ZARINPAL_SANDBOX=false شود.
- PUBLIC_BASE_URL باید دامنه واقعی با HTTPS باشد.
- قیمت‌ها در فایل env بر حسب تومان‌اند؛ سرور مبلغ را برای API زرین‌پال به ریال (×10) تبدیل می‌کند.
- هرگز پرداخت را فقط با پارامتر بازگشت مرورگر موفق اعلام نکنید؛ سرور تراکنش را با API درگاه Verify می‌کند.

محدودیت‌های فعلی و کارهای لازم پیش از انتشار عمومی
--------------------------------------------------
- این نسخه یک زیرساخت پرداخت اولیه است، نه فروشگاه کامل production.
- حساب کاربری و تأیید ایمیل/شماره تلفن هنوز پیاده نشده؛ اشتراک فعلاً به شناسه مرورگر (کوکی امن) متصل می‌شود. پاک شدن کوکی یا عوض شدن دستگاه می‌تواند دسترسی را از دسترس خارج کند. قبل از فروش عمومی باید احراز هویت و بازیابی حساب اضافه شود.
- پنل مدیریت سفارش/بازپرداخت، فاکتور، پشتیبانی، مانیتورینگ، بکاپ و تست نفوذ هنوز لازم‌اند.
- قیمت پلن‌ها عمداً صفر گذاشته شده و خرید تا زمان تعیین قیمت غیرفعال است.
- پرداخت USDT عمداً غیرفعال است. قبل از فعال‌سازی باید ارائه‌دهنده/روش قانونی دریافت، شبکه دقیق، قرارداد توکن، تأیید تعداد تأییدهای شبکه، تطبیق پرداخت و رسیدگی به برگشت/اشتباه بررسی شود.
- قبل از دریافت پول واقعی، وضعیت مجوز، مالیات، شرایط استفاده، حریم خصوصی و مقررات درگاه را با مراجع مربوط بررسی کنید.
- سرور را پشت HTTPS و reverse proxy امن منتشر کنید؛ فایل .env، دیتابیس و پوشه node_modules نباید عمومی باشند.

نکته امنیتی
-----------
هیچ‌گاه کلید خصوصی، عبارت بازیابی کیف پول، رمز پنل یا کد یک‌بارمصرف را در فایل‌های سایت، چت یا مخزن کد قرار ندهید.
